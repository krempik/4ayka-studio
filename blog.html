SLINGOR.IO 1.4: мультиплеер на гравитационных пращах

2026-09-18 | GAMEDEV, MULTIPLAYER

SLINGOR — это .io-игра про космические пращи: облетаешь планету — получаешь разгон в 1.35 раза, собрал цепь собственных пращ — множитель до ×5. Смысл в том, что физика не на клиенте, а в небе — точнее, на сервере.

Архитектура

  • Сервер (FastAPI + WebSocket) считает всю симуляцию комнат по 30 Гц и раздаёт состояние клиентам ~16 раз в секунду — клиент просто «рисует»
  • Физика (game/physics.py) — чистая и детерминированная: берёт dt, двигает мир, никакого wall-clock и глобального random
  • Боты используют тот же вход, что и люди, и добивают комнату до толпы

Геймплей

  • Праща: обогнул планету на скорости → разгон ×1.35 и очки
  • Цепь пращ: ещё одна за 6 секунд → ×2, ×3 … ×5
  • Ядра: собирай; погиб — груз падает контейнером, который за 26 секунд исчезает
  • Бонусы: щит (отражает удар), буст (удвоенная тяга), магнит (тянет ядра)

Анти-абуз

Никто не любит читеров, поэтому на сервере: лимит размера фрейма, минимальный интервал между вводами, контроль частоты сообщений с авто-киком, таймаут на «молчаливый» сокет.

Всё покрыто 48 юнит-тестами на детерминированную физику, ИИ ботов и API. Играть: krempik.github.io/slingor

Симуляция:   30 Гц, сервер-авторитативная
Раздача:      ~16 Гц + мгновенные события
Тесты:        48 (physics / ai / api)
Версия:       1.4.0

Dungeon of the Void: рогалик на 100 этажей

2026-09-15 | GAMEDEV, CANVAS

Dungeon of the Void — 2D данджон-рогалик на голом Canvas. Никаких движков: 12 модулей, один requestAnimationFrame и очень много любви к детерминизму.

Что внутри

  • Процедурная генерация: каждый этаж собирается из сида — загрузил сейв, получил тот же мир
  • Фиксированный тик 30 Гц с аккумулятором и капом, чтобы игра не «догоняла» время после паузы
  • DPR-aware рендер: на экранах с плотностью 2–3x всё остаётся чётким, тайлы кэшируются
  • Три класса, пассивные умения, магазины, 11 книг лора, боссы и финальная победа
  • Сейвы в localStorage с версионированием и миграцией
  • EN/RU локализация и процедурная музыка через Web Audio

Как устроен код

Симуляция, рендер и UI жёстко разделены: чистая логика (`entities`, `worldgen`) вообще не касается DOM, `render` только читает игровое состояние, `ui` — только DOM. Это даёт легкость тестирования и редкую для таких проектов дисциплину.

Тик:      1000/30 мс, аккумулятор с капом 8 тиков
Модули:   12 IIFE, однонаправленные зависимости
Procedural: сид → мир, без Math.random в спавне
Статус:   играбелен от старта до победы

Проект ещё на полировке, но проходится «из коробки». Следи за блогом — анонс релиза будет тут.

H4ck Messenger: E2E-шифрование своими руками

2026-09-10 | APPS, SECURITY

H4ck Messenger — мессенджер, в котором сервер не может прочитать сообщения. Не маркетинг, а реализация на Web Crypto API.

Как устроено шифрование

  1. При регистрации генерируется пара RSA-2048; публичный ключ уходит на сервер, приватный остаётся в браузере
  2. На каждое сообщение создаётся одноразовый ключ AES-256-GCM
  3. Сообщение шифруется AES, сам AES-ключ заворачивается RSA-ключом получателя
  4. На сервер уходит только шифротекст — расшифровать его без приватного ключа невозможно

Стек

Backend:   Python, FastAPI, SQLAlchemy, WebSocket
Frontend:  Vanilla JS, Web Crypto API, PWA
Auth:      JWT (access + refresh), PBKDF2-SHA256
DB:        SQLite
Публикация: Cloudflare Tunnel

Что умеет

  • Личные чаты с E2E и групповые чаты
  • Отправка файлов, статусы онлайн, индикатор набора
  • Прочитано/доставлено, редактирование и удаление
  • Админ-панель с баном и мод-логами

Открыть: krempik.github.io/messenger

4ayka-kit: бэкенд из 16 строк YAML

2026-09-08 | TOOLS, PYTHON

4ayka-kit — тулкит, который мы делаем для себя: вместо рутинных FastAPI-сервисов пишем короткую спеку и получаем рабочий бэкенд со всеми примочками.

Спека → сервис

project: { name: notes, title: Notes, auth: jwt }
resources:
  notes:
    fields: { title: str, body: text, tags: 'list[str]' }
    crud: full

ayka gen собирает модели, схемы, роутеры, JWT-авторизацию, rate limit и авто-миграцию БД. Дальше просто поднимаешь uvicorn app.main:app.

Состав

  • ayka.auth — PBKDF2, access/refresh JWT, зависимость авторизации
  • ayka.db — schema + безопасная авто-миграция без потери данных
  • ayka.middleware — IP-rate limiter (multiproxy-aware)
  • ayka.files — MIME-guard для загрузок
  • ayka.version — версии в одном месте
  • ayka.scanner / ayka ctx — сканирование проекта в компактный контекст для ИИ

Покрыт 48 тестами, включая полный e2e-прогон сгенерированного приложения. Репозиторий: github.com/krempik/4ayka-kit

Команды CLI:
  ayka new fastapi myapp   # каркас из спеки
  ayka gen                 # генерация app/ + CI + тесты
  ayka ctx [DIR] --ai      # контекст проекта для агента
  ayka version bump minor  # версия в одном месте

Почему Vanilla JS, а не фреймворк

2026-09-05 | JS, OPINION

«Используй React/Svelte/что-угодно» — стандартный совет. Мы его не слушаем. Вот почему.

Зависимости — это проблемы

  • node_modules чудовищных размеров
  • Лицензии, которые никто не читал
  • Уязвимости в транзитивных пакетах
  • Обновления, которые ломают совместимость

Vanilla JS покрывает 95% задач

DOM? querySelector, classList, addEventListener. AJAX? fetch. Реалтайм? WebSocket. Криптография? crypto.subtle. Игры? Canvas + requestAnimationFrame.

Когда фреймворк оправдан

Большие SPA с тяжёлым состоянием, десяток разработчиков, сложные формы. Для микропроектов, игр и тулзов vanilla проще, быстрее и понятнее.

Наш мессенджер — vanilla. Наши игры — vanilla. Инструменты — vanilla. Подход менять не планируем.

HTML5 Canvas: игровой цикл для начинающих

2026-09-01 | TUTORIAL, CANVAS

Основа любой Canvas-игры — цикл requestAnimationFrame. Минимум теории, максимум кода.

Базовый цикл

function gameLoop(ts) {
    update(dt);   // логика
    draw();       // отрисовка
    requestAnimationFrame(gameLoop);
}
requestAnimationFrame(gameLoop);

Фиксированный шаг — правильно

Если физика на клиенте, шаг времени должен быть стабильным. Накапливаем время и выполняем симуляцию фиксированными тиками:

const STEP = 1000 / 30;
let acc = 0, last = 0;
function frame(ts) {
    acc += Math.min(ts - last, 250);
    last = ts;
    while (acc >= STEP) { update(STEP); acc -= STEP; }
    draw();
    requestAnimationFrame(frame);
}
  • Кап аккумулятора (250 мс) спасает от «спирали смерти» при фоне вкладки
  • Такой паттерн используется в Dungeon of the Void

Коллизии

function collides(a, b) {
    return a.x < b.x + b.w && a.x + a.w > b.x &&
           a.y < b.y + b.h && a.y + a.h > b.y;
}

DPR: чтобы не было мыла

На экранах с плотностью 2–3x растянутый канвас выглядит размытым. Учитывай devicePixelRatio и масштабируй контекст.

const dpr = Math.min(devicePixelRatio || 1, 2);
canvas.width = width * dpr;
canvas.height = height * dpr;
ctx.setTransform(dpr, 0, 0, dpr, 0, 0);

Теперь хватит читать — пиши свою первую игру.

FastAPI за 30 минут: REST API для микропроектов

2026-08-28 | PYTHON, BACKEND

FastAPI — фреймворк, на котором построены бэкенды студии: лидерборд T-Blocks, комнаты SLINGOR и H4ck Messenger.

Минимальный сервер

from fastapi import FastAPI

app = FastAPI()

@app.get("/")
def root():
    return {"status": "online"}

WebSocket

@app.websocket("/ws")
async def ws(websocket: WebSocket):
    await websocket.accept()
    data = await websocket.receive_json()
    await websocket.send_json({"ok": True})

SQLAlchemy

Вместе со SQLite это закрывает весь «микропроект» от схемы до реального времени. А если сервисов становится много — на помощь приходит 4ayka-kit, который генерирует это из YAML.

Стек студии для бэкенда:
  FastAPI + SQLAlchemy + SQLite
  WebSocket для реалтайма
  JWT (PBKDF2 хеши) для авторизации
