H4ck Messenger: E2E шифрование без компромиссов

2026-08-26 | SECURITY, E2E | ~500 строк

Мессенджер, где сервер не может прочитать твои сообщения. Не маркетинг — а реальная реализация.

Архитектура шифрования

При регистрации генерируется RSA-2048 ключевая пара. Публичный ключ отправляется на сервер, приватный — остаётся в браузере.

При отправке сообщения:

  • Генерируется одноразовый AES-256-GCM ключ
  • Сообщение шифруется этим ключом
  • AES-ключ шифруется RSA-публичным ключом получателя
  • На сервер уходит только зашифрованный текст

Стек

 Backend:   Python, FastAPI, SQLAlchemy, WebSocket
 Frontend:  Vanilla JS, Web Crypto API
 DB:        SQLite (разработка) / PostgreSQL (прод)
 Протокол:  WebSocket (реалтайм)

Что сервер видит

Только зашифрованный текст. Без ключей расшифровать невозможно. Аутентификация — по токенам, пароли хэшируются bcrypt'ом.

Сообщения хранятся в БД в зашифрованном виде. Даже если базу украдут — данные бесполезны без приватных ключей пользователей.

2026-08-25 | JS, OPINION | ~300 строк

«Используй React/Vue/Svelte» — стандартный совет. Мы его не слушаем. Вот почему.

Зависимости — это проблемы

Каждый npm-пакет — это:

  • node_modules размером с smallpox
  • Лицензии, которые ты никогда не читал
  • Уязвимости в транзитивных зависимостях
  • Обновления, которые ломают обратную совместимость

Vanilla JS покрывает 95% задач

DOM манипуляции? querySelector, classList, addEventListener. AJAX? fetch. Реалтайм? WebSocket. Криптография? Crypto. Рисование? Canvas.

Когда фреймворк оправдан

Большие SPA с сложной state management. Многословные формы. Командная разработка с 10+ людьми. Но для микропроектов, игр, тулзов — vanilla быстрее и проще.

Наш мессенджер — vanilla JS. Наша игра — vanilla JS. Все инструменты — vanilla JS. И мы не планируем менять подход.

Столкновения

function collides(a, b) {
    return a.x < b.x + b.w &&
           a.x + a.w > b.x &&
           a.y < b.y + b.h &&
           a.y + a.h > b.y;
}

Криптография в браузере: AES, RSA и Web Crypto API

2026-08-23 | CRYPTO, SECURITY | ~500 строк

Web Crypto API — промышленная криптография прямо в браузере. Не поллифилл, не упрощённая версия — а настоящий стандарт.

AES-256-GCM

Симметричное шифрование. Один ключ для шифрования и расшифровки. Быстрое, подходит для данных.

const key = await crypto.subtle.generateKey(
    { name: 'AES-GCM', length: 256 },
    true, ['encrypt', 'decrypt']
);

RSA-OAEP

Асимметричное шифрование. Два ключа: публичный (шифрует) и приватный (расшифровывает). Медленное, подходит для передачи ключей.

Смешанный подход

В реальных E2E-системах (Signal, WhatsApp) используют гибридный подход:

  • RSA шифрует AES-ключ
  • AES шифрует данные
  • Получатель расшифровывает RSA-ключ, потом данные

Именно так работает H4ck Messenger. Код — на GitHub.

from fastapi import FastAPI

Для реалтайма — встроенные WebSocket:

@app.websocket("/ws/{token}")

    await websocket.send_json({"ok": True})

H4ck Messenger 4.0: E2E мессенджер с нуля

2026-08-26 | MAJOR RELEASE, MESSENGER, E2E | ~3000 строк

Первая версия H4ck Messenger — зашифрованный мессенджер, построенный за один день. Никаких фреймворков, никаких компромиссов. FastAPI + WebSocket + Web Crypto API + Vanilla JS.

Зачем ещё один мессенджер?

Потому что существующие либо закрытые (WhatsApp, Telegram), либо сложные в развёртывании (Matrix). Мы хотели мессенджер, который можно запустить одной командой, где сервер не видит сообщения.

Архитектура шифрования

При регистрации генерируется RSA-2048 ключевая пара:

  • Публичный ключ уходит на сервер
  • Приватный ключ остаётся в localStorage браузера
  • Сервер хранит только зашифрованные данные

При отправке сообщения:

  • Генерируется одноразовый AES-256-GCM ключ
  • Сообщение шифруется AES'ом
  • AES-ключ шифруется RSA-публичным ключом получателя
  • На сервер уходит: iv:ciphertext

Стек

Backend:   Python 3, FastAPI, SQLAlchemy, WebSocket
Frontend:  Vanilla JS, Web Crypto API
DB:        SQLite
Auth:      JWT (HS256), bcrypt хеши
Realtime:  WebSocket

Что реализовано

  • Регистрация и логин с JWT-токенами
  • E2E шифрование: RSA-2048 + AES-256-GCM
  • Личные и групповые чаты
  • Отправка файлов (до 100 МБ)
  • Статус «онлайн/offline» в реальном времени
  • Индикатор набора текста
  • Прочитано/доставлено (read receipts)
  • Редактирование и удаление сообщений

Клиент

Один HTML-файл + один JS-файл. Никакого сборщика, npm, webpack. Открываешь — и работает. CSS-переменные для тем, адаптивный дизайн, mobile-first.

Сервер

FastAPI с WebSocket-эндпоинтом. SQLAlchemy + SQLite. Cloudflare Tunnel для публичного доступа. Rate-limiting, JWT-авторизация, CORS.

Исходный код — на GitHub. Запуск: pip install -r requirements.txt && python -m uvicorn server.main:app.

H4ck Messenger 5.0 / T-Blocks 4.0: самое масштабное обновление

2026-08-27 | MAJOR RELEASE, MESSENGER, PWA | ~12000 строк изменений

Это релиз, который превращает мессенджер из «просто работает» в полноценную платформу. И T-Blocks тоже обновился.

Push-уведомления (Web Push API)

Теперь сообщения приходят даже когда вкладка закрыта. Реализовано через Service Worker + VAPID ключи:

  • Генерация P-256 ключей при первом запуске
  • Подписка на push через navigator.serviceWorker.pushManager
  • Отправка уведомлений с сервера через Web Push протокол
  • Клики по уведомлению открывают чат

Сервер хранит подписки в таблице push_subscriptions, клиент автоматически переподписывается при смене ключей.

Социальные фичи

  • Реакции на сообщения — эмодзи под сообщением, счётчики, toggle по клику
  • Ответы/цитирование — свайп/долгое нажатие → «Ответить», превью в UI
  • Закрепленные сообщения — pinned_message_id в чате, баннер в хедере
  • Mentions (@username) — парсинг на фронте, уведомления через WS
  • Темы чата — theme_color в настройках группы
  • Исчезающие сообщения — таймер 1ч/24ч/7д, автоочистка фоновым кроном
  • Статусы профиля — поле status в User

Медиа

  • Голосовые сообщения — MediaRecorder API → WebM/Opus → загрузка как файл с длительностью
  • Превью ссылок (Open Graph) — фетч og:title/image/description при вставке URL, кэш в link_previews
  • Стикеры/паки — JSON паки, таблицы sticker_packs/stickers, пикер в UI

Приватность и безопасность

  • Блокировка пользователей — таблица blocks, фильтр в списке пользователей и WS
  • Скрытые чаты (PIN) — флаг is_hidden + bcrypt-хеш PIN, разблокировка через модалку
  • Экспорт чата (JSON) — GET /api/chats/{id}/export для GDPR
  • Самоуничтожение аккаунта — DELETE /api/me, каскадное удаление всех данных

Админ-панель и модерация

  • UI в клиенте (шестерёнка для админа kremp)
  • Статистика: пользователи, чаты, сообщения, онлайн, DAU

  • Таблица чатов с удалением
  • Мод-логи: кто/что/когда удалил/забанил
  • Удаление сообщений модератором
  • Эндпоинты: /api/admin/*, защита через is_admin флаг

PWA и офлайн

  • Service Worker — кэш статики, офлайн-работа, стратегия Stale-While-Revalidate
  • Background Sync — очередь исходящих сообщений в IndexedDB, отправка при появлении сети
  • App Shortcuts — «Новый чат», «Профиль» в меню иконки

Техдолг и инфраструктура
